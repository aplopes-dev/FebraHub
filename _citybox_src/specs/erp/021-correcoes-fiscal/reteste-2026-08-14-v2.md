## N1 🔴 — Nenhuma escrita de Séries funciona: permissão que não existe

A leitura foi corrigida, mas **as 4 operações de escrita retornam 403**.

```
GET    /v1/companies/:id/sequences   → 200  ✅
POST   /v1/companies/:id/sequences   → 403  {"message":"Forbidden resource"}
```

`Forbidden resource` vem do `PermissionGuard`, **não** da `CompanyAccessPolicy` (que devolveria 404).

### Causa-raiz

As 4 rotas de escrita exigem `fiscal.sequences.manage`:

| Rota | Permissão exigida |
|---|---|
| `POST /v1/companies/:id/sequences` | `fiscal.sequences.manage` |
| `PATCH /v1/sequences/:id/number` | `fiscal.sequences.manage` |
| `PATCH /v1/sequences/:id/active` | `fiscal.sequences.manage` |
| `DELETE /v1/sequences/:id` | `fiscal.sequences.manage` |
| `GET /v1/companies/:id/sequences` | `fiscal.documents.view` ✅ |

Mas em `services/fiscal-api/src/shared/infra/http/decorators/permissions.ts`, **`fiscal.sequences.manage` não existe em lugar nenhum**:

```ts
const FISCAL_PERMISSIONS = [
  'fiscal.companies.manage',
  'fiscal.certificates.manage',
  'fiscal.documents.manage',
  'fiscal.documents.view',
] as const;                       // ← sem fiscal.sequences.manage

fiscal_operator: [ ...as mesmas 4... ]
```

E o `PermissionGuard` só libera com `platform.admin` ou com a permissão exata. Como `fiscal_operator` (a role do service account) não a tem e o mapa não a concede a ninguém, **nenhum caller consegue escrever série** — nem o service account, nem um usuário comum.

Só `platform_admin` passa, e é justamente o perfil que não foi usado no teste anterior — por isso o problema não apareceu antes.

### Correção

Decidir explicitamente se `fiscal.sequences.manage` é uma permissão nova (então adicioná-la a `FISCAL_PERMISSIONS` e a `fiscal_operator`) ou se as rotas deveriam usar `fiscal.documents.manage` (que já existe e já é concedida). Não deixar as duas grafias convivendo.

## N4 🟢 — `rateLabel` não cobre `undefined`

```ts
export function rateLabel(rate: number | null): string {
  return rate === null ? "—" : `${rate}%`;   // undefined → "undefined%"
}
```

Foi o que produziu o `undefined%` visível. Mesmo depois do deploy da API o `null` é legítimo (ICMS tem alíquota por UF, não um número único), então vale trocar por checagem nullish e conferir `taxSituationLabel` pelo mesmo critério.
